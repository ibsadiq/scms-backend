# Canonical Curriculum JSON V2 — Developer Contract

**Version:** 2.0  
**Status:** Authoritative — this document is the single source of truth for all PDF-to-JSON extraction.

---

## 1. Root Structure

```json
{
  "schema_version": "2.0",
  "curriculum": { ... },
  "source": { ... },
  "grades": [ ... ]
}
```

| Field | Type | Required | Description |
|---|---|---|---|
| `schema_version` | `"2.0"` | ✅ | Literal string. Selects V2 import path. |
| `curriculum` | object | ✅ | Curriculum identity. |
| `source` | object | ✅ | Provenance of the source document. |
| `grades` | array | ✅ | Non-empty list of grade objects. |

---

## 2. `curriculum` Object

```json
{
  "name": "NERDC Basic and Senior Secondary Curriculum",
  "authority_type": "NERDC",
  "authority_name": "National Educational Research and Development Council",
  "version": "2025",
  "description": "",
  "effective_from": null,
  "effective_to": null
}
```

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | string | ✅ | Must match an existing `Curriculum.name` or be used with `--create-curriculum`. |
| `authority_type` | string | | Maps to `CurriculumAuthority` enum. |
| `version` | string | | Used for matching alongside `name`. |

---

## 3. `source` Object

```json
{
  "title": "Nigeria New Education Curriculum, 2025 — JSS 1–3 and SSS 1–3",
  "authority": "NERDC",
  "publication_year": 2025,
  "version": "2025",
  "original_filename": "nerdc_2025_jss_sss.pdf",
  "source_type": "PDF",
  "checksum_sha256": "61b748e908836654ceab660e6a1e9657...",
  "source_reference": "JSS and SSS Scheme of Work",
  "metadata": {}
}
```

- `checksum_sha256` must be exactly 64 lowercase hex characters if provided.
- `checksum_sha256` is used for idempotent source deduplication: importing the same PDF twice reuses the `CurriculumSource` record.

---

## 4. Grade Object

```json
{
  "grade": "SS1",
  "subjects": [ ... ]
}
```

`grade` must match one of SSync's normalized grade codes: `BASIC_1`–`BASIC_6`, `JSS_1`–`JSS_3`, `SS_1`–`SS_3`. Aliases like `SS1`, `SSS1`, `Senior Secondary 1` are normalized automatically.

---

## 5. Subject Object

```json
{
  "subject": "Mathematics",
  "topics": [ ... ],
  "published_schemes": [ ... ],
  "resources": [ ... ]
}
```

- `topics`, `published_schemes`, `resources` may be empty arrays.
- A `CurriculumSubject` mapping must exist in the DB before import.

---

## 6. Topic Object

```json
{
  "topic_key": "number-base-system",
  "name": "Number Base System",
  "order": 1,
  "theme": "Number and Numeration",
  "content_summary": "",
  "subtopics": [
    {"name": "Conversion from one base to base 10", "order": 1},
    {"name": "Arithmetic operations in number bases", "order": 2},
    {"name": "Application to computer programming", "order": 3}
  ],
  "learning_objectives": [
    {"description": "Convert numbers between bases", "order": 1, "subtopic_ref": null}
  ],
  "guidance": null,
  "_source": {
    "page_start": 206,
    "page_end": 206,
    "reference": "",
    "raw_topic": "Number Base System",
    "raw_content": ""
  }
}
```

### `topic_key` Rules

- A URL-safe slug derived from `name`.
- Must be **unique within `(grade, subject)`** in the payload.
- Never contains term information.
- Generation formula:
  ```python
  import re, unicodedata
  def make_topic_key(name):
      name = unicodedata.normalize("NFKD", name).encode("ascii", "ignore").decode()
      name = name.lower().strip()
      name = re.sub(r"[^a-z0-9\s-]", "", name)
      name = re.sub(r"[\s-]+", "-", name)
      return name.strip("-")
  ```
- Explicit override: supply `topic_key` to disambiguate genuine collisions.

### `theme` Rules

- **Pedagogical strand**, not a term label.
- ✅ `"Number and Numeration"`, `"Algebra"`, `"Civic Education"`
- ❌ `"First Term"`, `"Second Term"`, `"Term 1"` ← validator ERROR

### `subtopics`

V2 format (required for new extractions):
```json
{"name": "Conversion from one base to base 10", "order": 1}
```
V1 format (plain strings) is tolerated and auto-normalised internally but should not be generated by new extractors.

### `_source`

Mandatory for new extractions. Preserves verbatim PDF evidence. Not stored in a dedicated DB field but propagated to `CurriculumTopic.source_page_start`, `.source_page_end`, `.source_reference`.

## 7. Published Scheme Object

```json
{
  "name": "Published Scheme of Work",
  "version": "2025",
  "description": "",
  "_source": {
    "page_start": 204,
    "page_end": 220,
    "reference": "SS1 Mathematics Scheme of Work"
  },
  "entries": [ ... ]
}
```

One scheme per subject is typical; multiple schemes (e.g. Term A vs Term B calendar variants) are supported.

---

## 8. Published Scheme Entry Object

```json
{
  "entry_key": "term-1-week-1-number-base-system",
  "term_number": 1,
  "week_start": 1,
  "week_end": null,
  "entry_type": "INSTRUCTION",
  "topic_ref": "number-base-system",
  "title": "Number Base System",
  "order": 1,
  "content_summary": "",
  "subtopic_refs": [
    "Conversion from one base to base 10",
    "Arithmetic operations in number bases"
  ],
  "learning_objective_refs": [1, 2],
  "teacher_activities": "",
  "pupil_activities": "",
  "learning_resources": "",
  "_source": {
    "page_start": 206,
    "page_end": 206,
    "reference": "First Term, Week 1",
    "raw_week": "1",
    "raw_topic": "Number Base System",
    "raw_content": ""
  }
}
```

### `entry_key` — Stable Reference Key

- **Required.** Must be unique within its published scheme.
- Used by `resources[].published_scheme_entry_ref` to link resources to specific entries.
- Not stored as a DB field; used only during import to build an in-memory `{entry_key: PublishedSchemeEntry}` map.
- Generation convention:
  ```
  term-{term_number}-week-{week_start}-{topic_key}
  ```
  For multi-entry weeks, add a suffix:
  ```
  term-1-week-1-fractions-continued
  term-1-week-1-fractions-review
  ```
- The validator produces ERROR on duplicate `entry_key` within a scheme.

### `term_number`

- `1`, `2`, or `3` only. Integer, not string.

### `week_start` / `week_end`

- Positive integers.
- `week_end` must be ≥ `week_start` when both present.
- Single-week entries: set `week_start`, omit `week_end` (or `null`).
- Range entries: set both (e.g. `week_start=7, week_end=10`).

### `entry_type`

| Value | When to use |
|---|---|
| `INSTRUCTION` | Teaching a topic from the curriculum |
| `REVISION` | Revision weeks (may or may not reference a topic) |
| `ASSESSMENT` | Continuous assessment period |
| `EXAMINATION` | Terminal/mock examination week |
| `BREAK` | Midterm break, public holiday, etc. |
| `PREPARATION` | Pre-exam preparation / reading week |
| `CLOSING` | End-of-term closing ceremony |
| `OTHER` | Unclassifiable |

`BREAK` and `EXAMINATION` entries should have `topic_ref: null`.

### `topic_ref`

References a `topic_key` defined in this subject's `topics` array. `null` for non-instructional entries.

### `subtopic_refs`

List of subtopic **names** (case-insensitive lookup). The referenced subtopics must exist in the topic identified by `topic_ref`.

### `learning_objective_refs`

List of integer `order` values referencing objectives in the topic identified by `topic_ref`.

## 9. Resource Object

```json
{
  "resource_type": "PRESCRIBED_TEXT",
  "title": "Redemption Road",
  "content": "",
  "topic_ref": null,
  "published_scheme_entry_ref": null,
  "order": 1,
  "metadata": {
    "category": "African Prose",
    "author": "Elma Shaw",
    "authority": "WAEC",
    "examination": "WASSCE",
    "valid_from": 2026,
    "valid_to": 2030
  },
  "_source": {
    "page_start": null,
    "page_end": null,
    "reference": "WASSCE Harmonized Literature Text List 2026–2030"
  }
}
```

### `resource_type`

| Value | Usage |
|---|---|
| `PRESCRIBED_TEXT` | Set texts mandated by an examining body |
| `RECOMMENDED_TEXT` | Recommended reading |
| `REFERENCE` | Textbook / reference book |
| `INSTRUCTIONAL_NOTE` | Inline teacher notes / content block |
| `EVALUATION` | Assessment tool or question bank |
| `ASSIGNMENT` | Homework or classwork |
| `PRACTICAL` | Lab/practical resource |
| `EXAMPLE` | Worked example |
| `OTHER` | Fallback |

### `topic_ref`

Optional. References a `topic_key`. Set when resource belongs to a specific topic.

### `published_scheme_entry_ref`

Optional. References an `entry_key` in this subject's `published_schemes[*].entries`. Set when a resource is scoped to a specific lesson entry (e.g. a Chemistry instructional note belongs to Week 1).

**The `entry_key` reference is resolved in-memory at import time.** It is not a database column.

---

## 10. Cross-Reference Summary

```
topics[].topic_key
    ←── published_schemes[].entries[].topic_ref
    ←── resources[].topic_ref

published_schemes[].entries[].entry_key
    ←── resources[].published_scheme_entry_ref

topics[].subtopics[].name
    ←── published_schemes[].entries[].subtopic_refs[]

topics[].learning_objectives[].order
    ←── published_schemes[].entries[].learning_objective_refs[]
```

---

## 11. Term / Theme Separation

> **Critical rule:** `term` and `theme` are fundamentally different.

| Concept | Where it lives | Example |
|---|---|---|
| Term (schedule) | `published_schemes[].entries[].term_number` | `1`, `2`, `3` |
| Theme (pedagogical strand) | `topics[].theme` | `"Number and Numeration"` |

Never put `"First Term"`, `"Second Term"`, `"Term 1"` in `topics[].theme`. The validator will reject this with an ERROR.

---

## 12. Idempotency Guarantees

| Entity | Lookup key | On match |
|---|---|---|
| `CurriculumSource` | `(curriculum, checksum_sha256)` | REUSE |
| `Topic` | `(grade_level, subject, name__iexact)` | REUSE |
| `CurriculumTopic` | `(curriculum_subject, topic)` | UPDATE if changed |
| `SubTopic` | `(topic, name__iexact)` | REUSE |
| `LearningObjective` | `(curriculum_topic, order)` | UPDATE if changed |
| `CurriculumGuidance` | `(curriculum_topic,)` | UPDATE if changed |
| `PublishedScheme` | `(curriculum_subject, name, version)` | REUSE |
| `PublishedSchemeEntry` | `(published_scheme, term_number, order)` | UPDATE if changed |
| `CurriculumResource` | `(curriculum_subject, curriculum_topic, published_scheme_entry, resource_type, title__iexact)` | UPDATE if changed |

Importing the same payload twice produces zero new records.

## 13. Validation

```bash
# Standalone (no server required)
uv run scripts/validate_curriculum_json.py --file data/my_curriculum_v2.json

# Full import (dry-run)
uv run scripts/import_curriculum_content.py \
  --file data/my_curriculum_v2.json \
  --tenant my-school \
  --dry-run
```

### Error Codes Reference

| Code | Severity | Trigger |
|---|---|---|
| `THEME_IS_TERM` | ERROR | `topics[].theme` matches `First Term`, `Second Term`, `Third Term`, etc. |
| `DUPLICATE_TOPIC_KEY` | ERROR | Two topics with same `topic_key` in a subject |
| `MISSING_ENTRY_KEY` | ERROR | Scheme entry has no `entry_key` |
| `DUPLICATE_ENTRY_KEY` | ERROR | Two entries share an `entry_key` in a scheme |
| `UNRESOLVED_TOPIC_REF` | ERROR | `topic_ref` not found in subject's topic_keys |
| `UNRESOLVED_ENTRY_REF` | ERROR | `published_scheme_entry_ref` not found in scheme entries |
| `INVALID_TERM` | ERROR | `term_number` not in `{1, 2, 3}` |
| `INVALID_WEEK_RANGE` | ERROR | `week_end < week_start` |
| `INVALID_ENTRY_TYPE` | ERROR | Not a valid `PublishedSchemeEntryType` |
| `INVALID_RESOURCE_TYPE` | ERROR | Not a valid `CurriculumResourceType` |
| `MISSING_TOPIC_KEY` | WARNING | `topic_key` absent (auto-derived, noted) |
| `MISSING_THEME` | WARNING | `topics[].theme` is empty |
| `INSTRUCTION_WITHOUT_TOPIC` | WARNING | `INSTRUCTION` entry has no `topic_ref` |
| `SUSPECTED_MERGED_WORDS` | WARNING | Probable PDF merge artefact |
| `PROBABLE_TRUNCATION` | WARNING | Probable truncated word |
